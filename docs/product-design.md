# Roadbook 自驾路书 MVP 产品设计

本文只描述当前代码和模板里用户能走到的行为。规划侧只记入口函数，不展开算法。

## 1. 产品一句话与目标用户

**一句话：** 把一句口语收成几天自驾，或高铁到站再租车的路书；生成后先看封面四句，再按天看取舍，改完能把这一版用真链接发给同伴。打开首页即可用。

**目标用户：** 已经想好大概从哪出发、去哪、玩几天的 1～4 人自驾同伴（预算可调到 5 人分摊）。他们要的是一页能看懂、能改一句、能转给同车人的路书，而不是订票、订房或攻略社区。

登录页文案是「周末出发，把路写清楚」。首页默认示例是北京到成都、7 天、明天出发。

## 2. 核心任务（Job）

用户要完成的事：在出发前把「去哪、怎么走、每天保什么、晚点砍什么、钱大概落不落在自己设的区间里」定成一版，并能让同伴打开同一版。

做成的标志不是下单，而是这三件事同时成立：

- 封面能用四句话读完这趟：去哪、最长一天、人均是否在自己设的区间、一条必知。
- 每一天标题下面有一句取舍：出发时间窗、今天要保住的锚点、晚点先砍的可选站。
- 要发给同伴时，海报或复制链接指向真实分享页；链接没写成时，不拿假二维码充数。

## 3. 主路径（打开 → 生成 → 看 → 改 → 发）

### 打开

用户直接打开路书首页，改表单或那一句口语后生成。中 / EN、浅色 / 深色在设置里。`/login` 会跳回首页。

### 生成

首页上方是需求区，不是结果。用户看到：

- 出发地、目的地（默认为北京、成都）、交换按钮、天数（1～14，默认 7）、出发日期（默认明天）。
- 偏好收成一行：「经典均衡 · 经典地标 · 舒适 · 全程自驾 · 高速优先」，右侧是「改偏好」。点开才看到节奏、主题、吃住玩档位、人均总预算滑块、同车人数（1～4）、燃油或纯电/混动、出行方式（全程自驾 / 高铁 + 到站租车）、高速优先或少走高速。
- 一句需求描述，最多 200 字。下面两个例子：北京 → 成都高铁+租车，北京 → 成都 7 天自驾。
- 主按钮「生成路书」，旁边状态「准备就绪」。

用户可以改城市和天数，或直接改那一句口语，然后点生成。句子里出发地、目的地、天数或时间没说清时，不会直接开算，而是打开底部半屏「说清需求」，追问后点「确定，写回需求描述」，句子回到输入框，再生成。句子已经和表单一致时，直接生成。

生成过程中结果区先露出骨架：标题、地图、里程和驾驶先显示「计算中」。状态依次写理解需求、落坐标、画出路线、查天气、整理行程。完成后按钮变成「重新生成」。整段需求收成一行（出发地 → 目的地 · 天数 · 日期 · 偏好），页面滚到封面。点这行「改需求」会把表单重新展开。

规划入口（函数名）：`parse_trip_request` 抽出出发地、目的地、天数和偏好；`plan_trip` / `plan_trip_async` 是完整规划；里面用 `_gather_amap_staged` 取路线，用 `_build_fast_itinerary` 直接交出可看的路书；出行方式为高铁+租车时由 `_maybe_attach_hsr` 附上班次和到站租车。前端对应 `startPlan`，走 `/api/plan` 分段推送。

### 看

封面是第一眼，由 `renderFirstGlance` 写成四句：

1. 去哪：出发地 → 目的地、天数、出发日期。
2. 最长一天：哪一天、从哪到哪、大约多少公里。没有单日里程时，退回全程驾驶时长。
3. 人均是否在档：大约多少钱，以及落在、超出或低于用户设的区间。
4. 一条必知：优先用「慎选」或第一条避坑；没有则用气候提示；再没有则用「适合谁」。

封面同时有标题、沿途城市、中国地图、天数 / 里程 / 驾驶 / 人均四格。里程和驾驶标注「按路线算出」，人均标注「估算」。

往下是按天条和途经城市条。每天标题下由 `dayPlayLine` 写一句，例如「早上 8 点前后出发 · 今天保「某地」 · 晚点先砍「某站」」。赶路日如果没有可砍站点，这句会带上当日大约公里数。当天还有夜宿城市、天气、今日全程导航。站点之间有转场说明。点某一天可只看那天。

手机上主视线是「每日行程」。费用和准备在另外两个页签：「费用预算」「避坑 & 准备」。宽屏右侧同时有副驾驶、预算、行前清单、避坑与住宿、必吃。改路书不靠右栏输入：有路书后，底部悬浮条才是副驾驶入口。

高铁+租车时，封面下多一张高铁卡：最多三条班次、时刻、二等座参考价、到站租车天数，以及「跳转 12306 购票」。卡上写明余票以官网为准，跨城段不计入全程自驾里程。这里是外链，不是在本页购票。

「适合谁」横条仍收起，不挡在封面和按天之间。行前清单有两处：封面地图下面一条，默认收起，展开后可勾选；右侧和「避坑 & 准备」里还有同一份清单。避坑、住宿、必吃带 Day（全程事项标「全程」）。点某一天时，这三块只留该天的条目。

### 改

看完不满意，用底部悬浮的「路书副驾驶」说一句。底栏是一条宽胶囊：左侧是最近一句回复（还没改过时是开场提示），右侧是「收藏」和「海报」。点左侧，对话区在悬浮条上方展开，里面是记录、快捷句和输入框。宽屏、窄屏都走这一块，不再把宽屏点按送到右栏。右栏副驾驶在宽屏仍能看到同一份记录，窄屏整块隐藏。

快捷句包括途经某城、跳过某城、改天数、把节奏调轻松或改成烟火美食。每天标题旁的「对话改这天」，以及途经条上的「加途经城」，都把半句放进悬浮对话的输入框（「Day N 换成」「中间加个」）。回复里的「看 DAY N」会收起对话区，再滚到那一天。对话区还开着时，改完不会把行程从底下拽走。

能识别并重算的说法包括：改天数、改出发地或目的地、途经城的增加 / 替换 / 跳过、节奏、主题、预算档或具体区间、同车人数、油车或电车、走高速或少走高速、指定某一天换成某个景点。途经城市条上的中间城市可以拖动排序。

回复末尾由 `_edit_consequence_line` 接一句后果：全程少开或多开大约多少公里（变化不足 5 公里则写几乎不变），以及人均仍在区间、低于区间，或超出区间并建议先砍哪个可选站。单日车程明显超节奏时，还会提醒可在中间再加一城。撤销回到上一次修改前，最多留 6 步，只在当次打开页面时有效。

规划入口：对话微调是 `apply_chat_edit_async`（前端 `sendChatEdit`，`/api/chat-edit`）；拖动途经顺序是 `apply_via_reorder_async`。两者都在新路书上重算，不另开一套方案列表。

站点上还可以：点名称或「导航」打开导航、复制地址、换一换、从备选库添加一站、移除、点序号标记已去过。分享页上看得到行程，但不能改站点。

预算卡上可改 1～5 人分摊、油车或电车，封面第三句和人均会跟着重算。清单可勾选，也可加一条自己的物品。这些改动写在本机，刷新后还能回到这一版草稿。

### 发

底部主按钮是「海报」，打开「发出这一版」。`drawPoster` 画出目的地、天数和出发日期、人数和人均、路线图、每天一行（当天亮点，并带晚饭店名或「住某城」）、底部里程 / 驾时 / 人均。高铁方案会标「高铁 + 租车」和一趟车次。

画海报时会请求写入公开链接。写成了才画二维码，并启用「复制链接」，说明文字改为这一版已可扫码或复制。失败则不画假二维码，复制按钮停在「链接未就绪」，海报上写「这一版链接暂未写成」，提示稍后重试或先下载图片给同伴对照。下载 PNG 随时可用。

同伴打开 `/s/…` 不必登录。页头说明只读，可看完整行程、预算和行前准备，免登录可导航。已登录的人可以「收藏到我的路书」或「据此修改」（复制到自己的首页再改，不改原分享）。未登录时收藏会先去登录；「我也要做路书」进登录页。

「收藏」把当前路书写进本机历史，最多 10 条。生成完成时也会自动记一条。历史入口在设置里的「历史路书」，不在底部常驻（底部历史按钮是隐藏的）。打开历史条目会回到封面。

意见反馈在设置里，手机上还有「反馈」按钮。分类是生成不准、不好用、想要的功能、其他，至少几个字，提交后状态行给回执。说明里写明不会上传完整路书。

中 / EN、浅色 / 深色在登录页和设置里切换，并记住在本机。

## 4. 已有能力清单

下列都在当前页面或规划入口里，用户能碰到。

- 打开首页即可用；规划 / 改路按 IP 做日配额。
- 一句口语生成：表单字段优先；句子不完整时半屏补全并写回需求；天数限制 1～14。
- 偏好一行：节奏（轻松慢游 / 经典均衡 / 特种兵）、主题（经典地标 / 亲子友好 / 人文摄影 / 烟火美食）、三档日均吃住玩、人均总预算区间、1～4 人、燃油或纯电/混动、全程自驾或高铁+到站租车、高速优先或少走高速。
- 两种走法：自驾路书；高铁+租车时展示班次参考、到站租车，并外链到 12306。预算里高铁方案会多出二等座估算和租车估算，并注明以官网票价为准。
- 生成后表单收成一行并滚到封面；可再展开改需求后重新生成。
- 封面四句（`renderFirstGlance`）：去哪、最长一天、人均是否在档、一条必知。另有地图、天气落到每天、沿途城市。
- 每天一句取舍（`dayPlayLine`）：出发时间窗、今日锚点、晚点先砍的可选站。
- 逐日站点、站间转场、今日导航、单点导航、复制地址、小红书搜索、换一换、添加或移除站点、标记已去过。
- 预算估算：油电、过路费、住宿、三餐、门票；可改人数和油电并重算是否在区间内。高铁方案另有票价参考和租车。
- 行前清单（证件、车辆、安全、装备、天气、健康、住宿等，随里程和目的地增减）可勾选、可自定义。地图下有一条默认收起的进度条；避坑、住宿、必吃带 Day，按天筛选时跟着收窄。
- 副驾驶改路线（`apply_chat_edit_async`）和拖动途经顺序（`apply_via_reorder_async`）。回复末尾写里程增减，以及人均是否仍在区间（`_edit_consequence_line`）。当次会话可撤销。
- 海报（`drawPoster`）：每天一行带晚饭或夜宿；真链接才画二维码，失败不画假码；可下载 PNG、复制链接。
- 分享页只读，免登录可看、可导航；登录后可收藏到本机或复制成自己的草稿。
- 历史路书夹：本机最多 10 条，从设置进入。生成完成会自动写入；底部「收藏」再写一次。
- 意见反馈。
- 中英文、深浅色；设置里可做手机预览。
- 本机记住上一版草稿，下次打开可恢复。

规划侧预算、清单、适合谁/慎选由 `_build_budget`、`_build_checklist`、`_build_fit_verdict` 生成，再交给上面的界面。默认不靠大模型重写正文；只有环境打开精修开关且在时限内返回时才会替换文案，用户界面没有单独的「精修」开关。

## 5. 明确不在本版本的范围

这些不做，页面上也不提供入口：

- 在本产品里订票、订房、查余票、比价、支付、会员、广告、佣金。高铁卡只展示参考班次并跳到 12306，余票和成交都在官网。
- 攻略广场，以及多套方案并排对比。一次只维护当前这一版路书。
- 底部「发现 / 我的」导航。底部是一条悬浮胶囊：左侧最新一句提示、右侧「收藏」和「海报」。点左侧才展开副驾驶对话，不是三个并排文字按钮。
- 海报编辑器。海报是按当前路书直接画出的，不能在画布上改字或改图。
- 新手蒙层。
- 多人同时改同一份路书。分享出去的是发出那一刻的只读副本；「据此修改」是复制到自己的本机草稿。
- 把偏好放回设置。偏好在生成表单那一行里，设置只管账号、外观、手机预览、历史和反馈。
- 分享成功后追问付费。

## 6. 成功标准：怎样算走完一次出行

一次出行在产品里走完，是用户能拿着这一版出发，而不是在本页完成订票或订房。同时满足下面四条，算走完：

1. **有一版可读的路书。** 已登录并生成成功。封面四句能回答去哪、最长的一天大约多远、人均落在/超出/低于所设区间、以及一条必知。表单已收成一行，视线在封面上。
2. **每天知道保什么、砍什么。** 打开按天行程，标题下那一句能看出出发时间窗、今天的锚点、晚点先砍哪一站（赶路日至少能看到当天里程或夜宿）。
3. **钱和改动说得清。** 若用副驾驶或拖动途经改过路线，回复末尾写明里程增减，并写明人均是否还在原来的区间。用户认可这一版，或撤销回到认可的那一版。
4. **同伴能打开同一版，或自己能在路上接着用。** 海报写成真实分享链接，同伴免登录打开后看到的是这一版的行程、预算和准备，且不能改到原件；或者用户下载了海报图，并清楚这张图在链接失败时不能当扫码入口。出发前清单在地图下可展开勾选，准备区里是同一份。路上可用导航，到过的站可标记已去过。

没走完的典型情况：句子没补全就停在「说清需求」；生成失败停在错误状态；分享没写成却把海报当成可扫码的入口；只在本机收藏，换一部手机就找不到这版路书。
